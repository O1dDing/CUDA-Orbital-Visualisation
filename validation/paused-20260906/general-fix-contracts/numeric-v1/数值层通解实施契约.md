## 2. 唯一的 AO 转换约定

优先保持现有内部角函数约定，统一导入转换，减少对已经共享该约定的分析和求值路径的扰动。内部纯壳顺序为 m=0,+1,-1,+2,-2,…，角函数包含 Condon–Shortley 相位；Gaussian 输入的纯 d/f/g 奇数 |m| 通过明确的基表示转换进入内部。s、笛卡尔 p/d/f、SP 拆分和 g 排列均由同一目录定义。Molden 的约定要按其格式和受支持来源单独核实，不能把 FCHK 转换无条件套到所有格式。

定义基函数列向量满足 φ_internal = T φ_source。一般可逆 T 必须使用：

```
C_internal = T^(-T) C_source
P_internal = T^(-T) P_source T^(-1)
S_internal = T S_source T^T
K_internal(R) = T K_source(R) T^T
```

只有 T 为带符号的正交排列时，才能简化为 C_internal=T C_source、P_internal=T P_source T^T。若含归一化缩放，系数与积分不能照搬同一乘法。每次转换保存其方向、输入/输出约定、壳与 AO 对应，以及参数来源。原始 MO 的输入身份、自旋、索引、能量、占据和原数据继续独立保存；这是表示转换，不是修饰输入波函数。

共用声明至少包含 source AO index、internal AO index、phase、scale、shell identity、angular component、normalization convention。MO、总/自旋/适用的其他密度和可选 overlap 的消费者均由这一个声明转换。禁止在 CUDA 端按分子名、MO 号或某一坐标顺序补符号。

纯壳到笛卡尔的展开一般是矩形映射，不套用上面的可逆公式。若 φ_pure=U φ_cart，则相同函数的笛卡尔系数为 C_cart=U^T C_pure；完整笛卡尔空间包含纯壳未覆盖的方向，不能宣称任意两种基组的全部 MO 一一相同。

独立参考约定由 [IOData 的 FCHK 格式实现](https://github.com/theochem/iodata/blob/main/iodata/formats/fchk.py) 和 [GBasis 的球谐转换实现](https://github.com/theochem/gbasis/blob/master/gbasis/spherical.py) 辅助核对；正式数值验收继续使用已冻结版本和本地来源哈希，不把远程主分支更新自动纳入运行批次。

## 3. 由基组直接计算完整 S

实现 `derive_ao_overlap_from_basis`，输入只有有效的基中心、壳、primitive、收缩参数及 AO 约定，不依赖 MO 是否齐全。对两个笛卡尔 primitive，使用 Gaussian 乘积中心 P=(αA+βB)/(α+β)，p=α+β，μ=αβ/p。

每个一维积分 J 的基础项为 J(0,0)=sqrt(π/p)，可用递推：

```
J(i+1,j) = (P-A) J(i,j) + i/(2p) J(i-1,j) + j/(2p) J(i,j-1)
J(i,j+1) = (P-B) J(i,j) + i/(2p) J(i-1,j) + j/(2p) J(i,j-1)
```

三维积分为 exp(−μ|A−B|²) 乘三个一维 J，再乘各 primitive 的已定义归一化和收缩系数，对 primitive 对累加。指数因子只计一次；s 到 g、SP、同中心和异中心都走统一递推。纯壳以明确的角函数展开转换笛卡尔积分。primitive 归一化与收缩归一化分别声明；不得为了让 CᵀSC 成为 I 而重归一化轨道或拟合 S。

对每个自旋的 C（n_AO×n_MO）计算全部 G=CᵀSC，保存对角、非对角和总最大残差；n_MO 可以小于 n_AO。参考 OLD-020 的 400 AO / 396 MO 必须完整得到 400×400 的 S，并保留缺失的四个 MO 方向，不补造轨道。

每份 S 记录维数、有限性、对称性残差、谱或可靠条件估计、最小特征值与处理范围。病态程度和不合格残差分别记录，不以病态标签直接删除输入，也不悄悄截去其空间。现有原库的固定检查门槛不因该实现而放宽。分解需要正交空间时，任何数值秩处理及丢失覆盖都必须明确报告。

输入提供可选 S 时，原矩阵保留为 producer 数据，与解析 S 和全部自旋 Gram 分别核对。若来源不一致，报告输入不一致及计算适用范围；不能因为字段存在就覆盖独立积分或填入“误差 0”。非法数值、缺项、未计算和合法零值分别编码。

## 4. 精度和并发边界

科学模型的 primitive 指数、收缩系数、MO 系数和占据使用 double；FCHK 原始小数解析后不先降为 float 再升回 double。原库 COEFF32-002 只量化了系数单项舍入误差，没有验证 primitive、坐标、快速指数、GPU 累加或图像输出。

GPU 上传使用专用缓冲和显式类型转换，分清 host 数据类型、device 数据类型和字节数。尤其不能把 double 系数首地址继续按 `basis_count*sizeof(float)` 直接复制。对降精度参数的非有限值、溢出和误差保留诊断；由实际渲染纹理和同点独立参考决定该统一路径是否合格。需要提高 GPU 精度时按一般数值条件或统一实现处理，不能对指定分子修饰结果。

CPU 积分、矩阵乘法、分解和批处理共同消费一次分配的线程额度。`dense_worker_count` 目前按硬件最多启 12 个工作线程，需要改成接受显式预算，不能在已有 Gaussian 预约之外再次自行获取 12 核。本轮实际配额仍由调度器保证总 12 核/128 GiB，未改正在计算的冻结策略。
